# Public Positioning

## One-Line Description

Aether Build Protocol is open infrastructure for turning physical project intent into machine-readable build packets and local quote-readiness workflows.

## Short Description

Aether Build Protocol is a local-first protocol seed for physical build coordination. It helps teams validate build intent, generate quote requests, normalize quote responses, and record negotiation or outcome events without becoming a marketplace or hiring workflow.

## Longer Thesis

Physical projects are still coordinated through fragmented drawings, spreadsheets, vendor emails, and unstructured quote requests. Aether Build Protocol provides a shared machine-readable layer between design intent and later build execution systems. The protocol is intentionally narrow: it preserves unknowns, flags licensed-trade and permit constraints, and structures quote-review work without selecting contractors or automating external actions.

## Hacker News / Reddit Caution Note

Lead with the protocol and guardrails, not hype. Avoid framing this as autonomous construction or AI replacing builders. Emphasize local files, human approval, and structured ambiguity reduction.

## Founder Explanation

The point of Aether Build Protocol is to make physical projects legible to software and reviewable by humans before routing, quoting, or execution ever happens. The long-term value is better coordination quality and a future trust surface, not pretending the protocol is already a marketplace or autonomous build system.

## Non-Hype Language Guidelines

- say local-only when describing the proof loop
- say human review required when describing any output
- say informational only when describing quote comparison
- avoid claims about contractor selection, hiring approval, or build approval
